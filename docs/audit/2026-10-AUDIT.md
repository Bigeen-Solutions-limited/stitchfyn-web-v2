## Pass 1: Inputs and trust boundaries (Rule 4)

The web app's inputs are what users type, URL parameters, API responses, and its own browser storage (IndexedDB offline queue, `localStorage` device id). Enforcement belongs to the API. This pass checks that the web doesn't turn untrusted data into code or markup, and doesn't keep credentials where scripts can read them.

### Checklist

| Item | Result | Evidence |
| --- | --- | --- |
| No `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function`, `document.write` | ✅ | `grep -rnE "dangerouslySetInnerHTML\|innerHTML\|eval\(\|new Function\|document\.write" src` finds nothing outside tests. Every server value is rendered as React text. |
| Links built from data can't run script | ✅ | The only `href` built from API data is the audit metadata link (`features/audit/auditPresentation.ts`), which accepts only `^https?://`. WhatsApp and SMS share links use `encodeURIComponent`. `window.open` calls use fixed schemes or `groupShareUrl`, with `noopener`. |
| `<img src>` from data | ✅ | Sources are Cloudinary `secureUrl` values, server-generated QR data URLs, or base64 fabric images the API returns. `<img>` doesn't run script. |
| Credentials not readable by injected script | ✅ | The access token is kept in memory (`features/auth/hooks/useAuth.ts`) and the refresh token is an httpOnly cookie set by the API. `localStorage` holds only a random device id, which isn't a secret (`lib/device-id.ts`). |
| Secrets not hardcoded | ✅ | The only build-time value is `VITE_API_URL` (`infrastructure/http/axios.client.ts`, `features/orders/seal.api.ts`). No keys are in the bundle. |
| Validation on input | ✅ (advisory) | Forms validate for usability only. The API is the boundary, and its gaps are in the API audit (P1-8). |
| Authorization on the resource | N/A here | Role-based hiding in the UI is a convenience. The API fixes from Pass 1 (payments, customer thread, dashboard scoping) are what enforce it. The tailor dashboard needed no change: `/analytics/overview` now returns only the tailor's own orders. |
| Webhooks | N/A | — |

## Pass 2: Dependencies (Rule 8)

### Checklist

| Item | Result | Evidence |
| --- | --- | --- |
| `npm audit`: every high and critical triaged | ✅ | Before: 3 critical, 2 high, 2 moderate, 1 low. After this PR: 2 critical and 1 moderate, all in the vitest test runner, which needs the vitest 4 major (W2-3). |
| Every package is imported | ❌ → fixed | `@vitest/ui` was never used (no `--ui` script) and carried a critical advisory. `@types/uuid` is redundant (uuid 14 ships its own types), and `@types/testing-library__jest-dom` is redundant (`@testing-library/jest-dom` 6 ships its own types and is loaded in `src/test/setup.ts`). All three were removed. `@emotion/react` and `@emotion/styled` have no imports, but MUI requires them as peers, so they stay. |
| Typosquatting, low downloads, maintainer change | ✅ | Every direct dependency is a mainstream package under its canonical name (react, @mui/*, @tanstack/react-query, axios, date-fns, zustand, uuid, vite, vitest, eslint). The lockfile resolves only from `registry.npmjs.org`, and every entry has an `integrity` hash. |
| Install scripts | ✅ | Only `esbuild` and `fsevents`, both dev-only and both expected (native binaries). |
| Hallucinated packages | ✅ | Every name in `package.json` resolves on the registry to the expected project. |
| Lockfile committed, CI uses `npm ci` | ✅ | `package-lock.json` is tracked (lockfileVersion 3), and `.github/workflows/ci.yml` runs `npm ci`. |
| Deprecated packages have a written reason | ✅ | No direct dependency is deprecated. Transitive: `glob@11` (from workbox, dev) and `whatwg-encoding` (from jsdom, dev). Both go away when their parents update, and nothing in this repo pins them. |
